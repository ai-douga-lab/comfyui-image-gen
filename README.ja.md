# comfyui-image-gen

[English](README.md)

LM Studio のチャットから、ローカルの VL モデル経由で **ローカル ComfyUI の Qwen Image 2.1** を使って画像を生成・編集するプラグインです。

- いつも通りローカルの VL モデル（Qwen3-VL など）と会話し、画像を頼むとモデルが `generate_image` ツールを呼び、ComfyUI が描きます。
- 添付画像には `[a1]`, `[a2]`, …、生成画像には `[v1]`, `[v2]`, … のラベルが付き、モデルはそれらの画像を**実際に見て**います。「この画像のりんごをお皿に載せて」と言えば、正しい画像が参照画像として ComfyUI に渡ります。
- 生成画像はプラグイン自身がチャットに表示します（ツール結果の 1MB 制限なし、フル解像度）。
- LM Studio で生成を止めると、ComfyUI 側のジョブもキャンセルされます。

```
あなた:   [apple.jpg, banana.png を添付] これをひとつのお皿に
チャット: [a1][a2]として画像をアップロードしました。[a1][a2]を入力して、画像の生成を開始します。
          （画像）
          [a1][a2]を入力して[v1] (りんごとバナナのお皿)を生成しました。
あなた:   この画像のお皿を青くして
チャット: [v1]を入力して、画像の生成を開始します。
```

## 必要なもの

- プラグイン対応の **LM Studio** と `lms` CLI
- **Node.js**（`lms dev` 用）
- LM Studio に読み込んだ **VL モデル**（Qwen3-VL 8B で動作確認）と、起動済みの **LM Studio ローカルサーバー**（既定 `http://127.0.0.1:1234`）
- Qwen Image 2.1 をセットアップ済みのローカル **ComfyUI**（既定 `http://127.0.0.1:8188`）

### ComfyUI 側

`workflows/` に Qwen Image 2.1 の参照画像→画像生成ワークフローを同梱しています。

| ファイル | 形式 | 用途 |
|---|---|---|
| `workflows/QI21_Ref2I.json` | UI | ComfyUI で開いて、確認・手動実行・編集する用 |
| `workflows/QI21_Ref2I_api.json` | API（*Export (API)*） | プラグインに組み込まれ、**Workflow (API format)** が空のときに使われる |

どちらも画像入力は ComfyUI 付属のサンプル `example.png` を指しています。プラグインが実際の画像に差し替えます。

ワークフローは次のモデルファイルを使います。

| 種類 | ファイル |
|---|---|
| 拡散モデル（`models/diffusion_models`） | `qwen_image_2.1_int8_convrot.safetensors` |
| テキストエンコーダ（`models/text_encoders`） | `qwen3vl_8b_int8_convrot.safetensors` |
| プロンプト書き換え用テキストエンコーダ（`models/text_encoders`） | `qwen3.5_9b_qwen_image_2.1_pe_i2i.int8_convrot.safetensors` |
| VAE（`models/vae`） | `texture_fix_vae_for_qwen_image_2.1_bf16.safetensors`（[madebyollin/texture-fix-vae-for-qwen-image-2.1](https://huggingface.co/madebyollin/texture-fix-vae-for-qwen-image-2.1)） |

また [RES4LYF](https://github.com/ClownsharkBatwing/RES4LYF) の `res_2s` サンプラーと、カスタムノード由来のノードをいくつか使います。`workflows/QI21_Ref2I.json` を ComfyUI にドラッグして、**ComfyUI Manager → Install Missing Custom Nodes** で確認するのが簡単です。環境が違う場合は自分のワークフローを使えます（[自分のワークフローを使う](#自分のワークフローを使う)）。

## インストール

```bash
git clone https://github.com/ai-douga-lab/comfyui-image-gen.git
cd comfyui-image-gen
npm install
lms dev
```

`lms dev` を実行している間、プラグインがビルドされて LM Studio に登録されます。

## LM Studio での設定

1. VL モデルを読み込み、ローカルサーバーを起動します（Developer タブ）。
2. チャットのモデル選択で **comfyui-image-gen** を選びます。
3. プラグイン設定の **Model** に、読み込んだ VL モデルの ID を入れます（`lms ps` で確認。例: `qwen/qwen3-vl-8b`）。
   **画像を添付するにはこの設定が必須です。** LM Studio はこのモデルを見て、チャットに画像をドロップできるかを決めます。空のまま（または画像非対応のモデル）だと、画像をドロップしたときに「Model does not support image input」になります。
4. 下のグローバル設定（ComfyUI URL など）を確認します。
5. ほかの画像系 MCP（ComfyUI の MCP や filesystem MCP など）を有効にしている場合は、このチャットではオフにしてください。モデルが画像を「見る」代わりに、それらのツールで開こうとすることがあります。

## 使い方

- **生成:**「木のテーブルの上の赤いりんごを描いて」
- **添付画像を参照:** 画像を添付して「この猫に帽子をかぶせて」。発言に添付した画像は自動的に参照画像になります（設定でオフにできます）。
- **生成画像の編集:**「この画像の背景を青くして」。「この画像」は直近の画像を指します。ラベルで明示もできます:「[a1] の猫を [v2] のソファに座らせて」
- **複数の参照画像:** 1 回の生成で最大 10 枚（ワークフローの画像スロットが 10 個）。
- **キャンセル:** LM Studio の停止ボタン。ComfyUI のジョブはキューから削除、または中断されます。

生成画像は、チャットの作業フォルダに、モデルが付けた英語のファイル名（例: `apple_on_plate.png`）で保存されます。**Also save images to this folder** を設定すると、日本語タイトルのファイル名でコピーも保存されます。

## 設定

チャットごと（プラグイン設定）:

| 設定 | 既定値 | 説明 |
|---|---|---|
| Model | （空） | エンドポイント上の VL モデルの ID |

グローバル:

| 設定 | 既定値 | 説明 |
|---|---|---|
| Base URL | `http://127.0.0.1:1234/v1` | チャットモデルの OpenAI 互換エンドポイント |
| ComfyUI URL | `http://127.0.0.1:8188` | ローカル ComfyUI サーバー |
| Workflow (API format) | （空 = 同梱） | *Export (API)* で書き出したワークフローのパス |
| Reference image format in prompt | `<image{n}>` | `[a1]`/`[v1]` の書き換え先。`{n}` はスロット番号 |
| Always use attached images as references | オン | モデルがプロンプトに書き忘れても、発言に添付された画像を参照画像に加える |
| Let the model comment on generated images | オフ | オン: 生成後にモデルが画像を見てコメント（遅くなる）。オフ: 画像を表示してすぐ終了。どちらでも、モデルは後で `[v1]`… を見られます |
| Generated image size (megapixels) | `0.5` | ComfyUI で生成する画像のサイズ（0.5 ≈ 720×720、1.0 ≈ 1024×1024、4.0 ≈ 2K）。「もっと大きく」などと頼んだときだけ、モデルが変えます |
| Image size sent to the model (megapixels) | `0.5` | チャットモデルに見せる画像をこのサイズに縮小（チャットフォルダにキャッシュ）。毎ターンすべての画像を送り直すため、大きい画像だと返答がとても遅くなります。ComfyUI には常に元の画像を渡します。`0` = 縮小しない |
| Also save images to this folder | （空） | すべての画像をタイトル名でここにもコピー |

## 自分のワークフローを使う

ComfyUI で **Export (API)** したワークフローのパスを **Workflow (API format)** に設定します。`workflows/QI21_Ref2I.json` を開いて手を加え、書き出すのが簡単です。プラグインはノードを ID で探すので、同梱ワークフローと同じ構成にするか、`src/comfy.ts` 先頭の ID を書き換えてください。

| 用途 | ノード ID | ノード |
|---|---|---|
| プロンプト | `74` | `PrimitiveStringMultiline`（`value`） |
| プロンプト拡張のオン/オフ | `76` | `PrimitiveBoolean`（`false` に設定） |
| 「Edit image1」：空の潜在画像ではなく image1 から生成を始める | `95` | `PrimitiveBoolean`（今は常に `false`。[TODO](#todo) 参照。なくても可） |
| サイズ | `29` | `ResolutionSelector`（`aspect_ratio`, `megapixels`） |
| バッチ数 | `56` | 整数（`value`、1 に設定） |
| シード | `7` | `RandomNoise`（`noise_seed`） |
| 参照画像 1〜10 | `39 40 41 42 47 57 58 59 60 61` | `LoadImage` |
| 参照画像のオン/オフ 1〜10 | `81`〜`90` | `ComfySwitchNode`（`switch`, `on_true`） |

使わない画像スロットはオフにし、その `LoadImage` ノードは実行前に取り除きます。

## しくみ

### 全体像

```
                       ┌──────────────────────── プラグイン ─────────────────────┐
LM Studio チャット ──► │ generator（src/generator.ts）                          │ ──► LM Studio ローカルサーバー上の
 （履歴・添付ファイル） │  ・テキスト＋ラベル付き画像でリクエストを組み立てる     │     VL モデル（OpenAI 互換 API）
                       │  ・画像と状況メッセージをチャットに表示する             │ ◄── テキスト / ツール呼び出し
                       │                    │ comfy_media.json（チャットごと）  │
                       │                    ▼                                   │
                       │ ツール generate_image（src/toolsProvider.ts, comfy.ts）│ ──► ComfyUI
                       │  ・ラベル→ファイル→<image1>…、アップロード、実行       │ ◄── 生成された PNG
                       └─────────────────────────────────────────────────────────┘
```

生成を含む 1 ターンは次のように進みます。

1. あなたがメッセージを送ります（画像付きのこともあります）。LM Studio はチャット履歴全体を渡して、プラグインの **generator** を呼びます。
2. generator はすべての画像にラベルを付け、テキストと画像を OpenAI 形式のリクエストにまとめて、LM Studio ローカルサーバー上の VL モデルにストリーミングで送ります。
3. モデルは `generate_image` のツール呼び出しで答えます。そのプロンプトには `[a1]` などのラベルが入っています。
4. generator は、ツール呼び出しを LM Studio に渡す前に「[a1]を入力して、画像の生成を開始します。」とチャットに出します。
5. LM Studio が**ツール**を実行します。ツールはラベルをファイルに変換して ComfyUI にアップロードし、ワークフローを実行します。結果は `[v1]` として保存し、短いテキストを返します。
6. LM Studio がもう一度 generator を呼びます（履歴の最後がツール結果になっています）。generator は新しい画像をチャットに表示し、そのままターンを終えるか（既定）、画像をモデルに見せてコメントさせます。

### なぜツール（MCP）ではなく generator なのか

最初は MCP サーバーとして作りました（ツールだけのプラグインでも事情は同じです）。画像は生成できましたが、実際に使うと何か所かで行き詰まりました。

- **モデルが自分の生成結果を見られない。** LM Studio はツールが返した画像をモデルに渡しません。そのため、モデルは生成した画像を確認も説明もできず、「この画像をもっと青く」と言われても参照する先がありませんでした。
- **ツールからはチャットが見えない。** ツールが受け取るのは、モデルが書いた引数だけです。添付画像を使うには、モデルが引数にファイルパスを書く必要があります。しかしモデルは LM Studio が添付ファイルをどこに保存しているか知らないので、存在しないパスを作り出していました。
- **画像の表示が難しい。** ツール結果として画像を返すと LM Studio の 1MB 制限にかかり、小さなプレビューしか出せませんでした。
- 時間のかかる生成は MCP のタイムアウト（既定 60 秒）に引っかかりました。

**generator** は、チャットの中でモデルの代わりになるプラグインです。LM Studio は generator に履歴全体（添付ファイルを含む）を渡し、generator が本物のモデルに何を送るか、チャットに何を書くかを決めます。これで上の問題がすべて解決します。

- 添付画像も生成画像も、generator がラベル付きでリクエストに直接入れられる。
- ツールが `[a1]` をファイルに変換するための対応表を、generator が書いておける。
- 生成画像を、ファイルを指す Markdown 画像としてチャットにフルサイズで出せる。ツール結果の制限は関係ない。

その代わり、generator は自分でモデルを呼び出す必要があります。プラグインに **Base URL**（LM Studio のローカルサーバー）と **Model** の設定が必要で、ローカルサーバーを起動しておく必要があるのはこのためです。

### 画像をモデルに渡すしくみ

添付ファイルは LM Studio が保存しています。generator はユーザーのメッセージごとに LM Studio からファイル一覧を受け取り（`ChatMessage.getFiles()`）、画像だけを選んでローカルのパスを取得します（`FileHandle.getFilePath()`）。そのファイルを読み込んで **Image size sent to the model**（既定 0.5 メガピクセル、JPEG）に縮小し、OpenAI チャット形式の base64 `image_url` パートとして送ります。各画像の直前には、ラベルを書いたテキストパートを置きます。

```jsonc
{ "role": "user", "content": [
  { "type": "text", "text": "[a1]" },
  { "type": "image_url", "image_url": { "url": "data:image/jpeg;base64,..." } },
  { "type": "text", "text": "[a2]" },
  { "type": "image_url", "image_url": { "url": "data:image/png;base64,..." } },
  { "type": "text", "text": "これをひとつのお皿に" }
]}
```

生成画像はツールメッセージに入れられません（OpenAI 形式でも多くのローカルのチャットテンプレートでも、そこにはテキストしか置けないためです）。そこで generator は、ツール結果の直後にユーザーメッセージを 1 つ差し込みます。中身は `[v1] (generated image)`、画像本体、「These are the images you just generated.」です。

毎ターン、履歴全体をこの形で組み立て直すので、モデルは毎回、会話中のすべての画像を見ています。何ターンも後で「最初の写真の猫」と言っても通じるのはこのためです。その分、画像の多い長い会話ではコンテキストを多く使います。

### モデルがどの画像のことか分かるしくみ

- **画像のすぐ横のラベル。** モデルは画像の直前に `[a1]` を見るので、名前と見えている内容を結び付けられます。
- **システムプロンプトの注記。** ラベルのつけ方を説明し、`generate_image` のプロンプトにはラベルを書くよう指示します。ツールで画像を開くことやファイルパスを推測することは禁止しています。直近の画像も名指しするので（「The most recent image in this conversation is [v2]」）、「この画像」は最新の画像を指すと分かります。Qwen など一部のチャットテンプレートは先頭のシステムメッセージを 1 つしか受け付けないため、この注記は既存のシステムプロンプトに追記しています。
- **自動参照。** 小さいモデルは、今添付された画像の `[a1]` を書き忘れがちです。今回のメッセージに添付された画像がプロンプトになければ、自動で追加します（`Using [a1] and [a2] as reference images: …`）。設定でオフにできます。
- **検証。** 存在しないラベルがプロンプトにあると、ツールは使えるラベルの一覧付きでエラーを返し、モデルがやり直せるようにします。

### ラベルとファイルを紐づけるしくみ

generator とツールは別々に動き、ツールはモデルが書いた引数しか受け取りません。両者は小さな対応表 `comfy_media.json` を共有しています。この表はチャットの作業フォルダ（`getWorkingDirectory()`）に置かれます。作業フォルダはチャットごとに別なので、別のチャットの画像が混ざることはありません。

```jsonc
{
  "attachments":     { "a1": "C:\\…\\apple.jpg", "a2": "C:\\…\\banana.png" },
  "turnAttachments": ["a1", "a2"],
  "variants":        { "v1": "C:\\…\\<チャットのフォルダ>\\apple_banana_plate.png" },
  "info":            { "v1": { "refs": ["a1", "a2"], "title": "りんごとバナナのお皿" } }
}
```

- **`a` ラベル**は登場順の番号です。チャットで最初に添付された画像が `[a1]` になります。generator が毎ターン履歴から数え直し、モデルを呼ぶ前に表へ書き込みます。`turnAttachments` は最新のメッセージの画像で、自動参照に使います。
- **`v` ラベル**は、ツールが結果を保存するときに付けます。次の空き番号で、振り直すことはありません。ファイルは、モデルが付けた英数字の名前でチャットの作業フォルダに保存します。`info` には、状況メッセージ用に参照画像とタイトルを記録します。
- ツール結果の末尾には `(comfy-gen: v1)` のような目印を付けます。generator には履歴しか見えないので、この目印で「このツール呼び出しで生成された画像」を知り、チャットとモデルに表示します。

ツールは実行時に、プロンプト中のラベルを最初に出てきた順に集め、入力スロット 1, 2, 3… を割り当てます。プロンプト中の各ラベルは **Reference image format in prompt** の書式に書き換えます（`[a1]` → `<image1>`）。各ファイルは ComfyUI にアップロードし（`/upload/image`）、そのスロットの `LoadImage` ノードに入れます。使わないスロットはスイッチをオフにし、その `LoadImage` ノードを取り除きます。その後、ワークフローをキューに入れ（`/prompt`）、終わるまで `/history` を確認し、結果をダウンロードします（`/view`）。

### キャンセル

ツールは LM Studio の中断シグナルを見ています。停止ボタンを押すと、ComfyUI のキューからジョブを削除し（`POST /queue {delete}`）、すでに実行中なら中断します（`POST /interrupt`）。

## 既知の制限

- LM Studio はツールが返した画像をモデルに渡さないため、プラグインが生成画像を自分で会話に差し込んでいます。プラグインが generator だからできることです。
- LM Studio は、ファイル名に日本語などを含むローカル画像を「External Image」と表示するため、チャット内のファイル名は英数字にしています。日本語名が欲しい場合はコピー先フォルダを使ってください。
- `a` ラベルはチャット履歴から数えるため、画像付きの過去のメッセージを編集・削除すると、それより後の添付画像の番号がずれることがあります。
- プラグインが出すメッセージ（「画像の生成を開始します」など）は今のところ日本語のみです。
